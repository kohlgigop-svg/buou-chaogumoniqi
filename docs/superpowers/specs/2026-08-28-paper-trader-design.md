# 模拟炒股游戏《大布偶证券交易所》设计规格（paper-trader）

- 日期：2026-08-28
- 状态：已与需求方逐节评审通过（6/6 节），本文为汇总规格
- 范围：第一版（V1）完整功能 + 部署；二期候选单列

---

## 1. 项目概述

一个多人在线模拟炒股网页游戏。行情为**纯模拟**：虚构股票池 + 真实 A 股规则 +
随机过程引擎，不接入真实行情数据，不使用真实公司名称。玩家注册即得初始资金
¥100,000，通过交易、打工、能力养成与贷款经营自己的资产，参与排行榜竞争。

**设计原则**
1. 服务端唯一权威：一切数值由服务端计算，客户端输入一律经校验。
2. 账实相符：所有资金变动走只追加流水（ledger），恒等式受测试保护。
3. 规则真实：A 股核心规则逐条照搬（见 §5）；虚构的只有标的与行情本身。
4. 数据驱动：全部平衡数值集中于 config 与 seed 数据，改数字不改代码。
5. 体量务实：目标并发几十人，架构按此裁剪（单进程 + SQLite），不过度设计。

**非目标（V1 不做）**：融资融券（做空）、打新申购、持仓质押贷、玩家间转账、
实操小游戏打工、期权期货、邮箱验证/找回（已明确取消）、原生 App。

## 2. 时间体系（全局唯一时钟）

| 常量 | 值 |
|---|---|
| 1 游戏交易日 | 60 现实分钟 |
| 换算 | 1 现实分钟 = 24 游戏分钟；8 游戏小时 = 20 现实分钟 |
| 交易日编号 | 从创世时刻（`GENESIS_TS`，环境变量）起连续编号 1,2,3…，无周末 |
| 引擎 tick | 3 现实秒（连续竞价时段每日约 1100 tick） |

**每交易日结构（现实分钟）**：开盘集合竞价 3 → 连续竞价 55 → 收盘集合竞价 1 →
日终结算 1。

**日终结算窗依序执行**：成交/委托日终清理（未成交委托自动撤销）→ T+1 持仓解冻 →
贷款计息与逾期推进 → 工资/课程结转 → 财报披露与分红除权 → ST/退市/IPO 状态推进 →
信誉更新 → 全服对账（§16 不变量）→ 自动备份 → 生成次日事件与种子。

**停机补跑**：引擎状态（当前日/相位/tick 序号/PRNG 状态/市场状态）每 tick 落盘。
进程重启后按墙钟计算应到达的 tick，用持久化种子**确定性补跑**全部错过的
tick（含撮合与日终结算）。补跑结果与不间断运行逐字节一致（受测试保护）。
玩家在停机期间的挂单照常参与补跑撮合。

## 3. 系统架构

单 Docker 容器、单 Node.js 进程、三层：

```
┌─────────────────────────────────────────────┐
│  Node.js 22 (TypeScript)                    │
│  ┌────────────┐  ┌───────────────────────┐  │
│  │ 行情引擎    │→│ Fastify API + WebSocket │←── 浏览器 (React SPA)
│  │ (tick 循环) │  │ + 静态文件托管          │  │
│  └─────┬──────┘  └──────────┬────────────┘  │
│        └──────┬─────────────┘               │
│        ┌──────▼──────┐                      │
│        │ SQLite(WAL) │  挂载持久卷 /data     │
│        └─────────────┘                      │
└─────────────────────────────────────────────┘
```

- 引擎与 API 同进程，通过内存直调；better-sqlite3 同步事务保证撮合原子性。
- 单进程即全局撮合串行化，天然无竞态；体量（几十人）远低于 SQLite 上限。
- 前端构建产物由 Fastify 托管，同源部署，无 CORS。

## 4. 行情引擎

### 4.1 股票池

48 只虚构股 + 综合指数（市值加权，基点 3000）+ 20 个板块指数（基点 1000）。
完整清单见附录 A：沪主板 25 只（`60xxxx`，±10%）、深主板 17 只（`00xxxx`，±10%）、
创业板 6 只（`30xxxx`，**±20%**）。名称为真实龙头的戏仿（如"黔台酒业"），
代码避开真实知名代码。每股 seed 数据含：总股本、初始价、波动档、β、派息倾向。

### 4.2 价格模型（每 tick，对数收益叠加）

```
r_stock = β·r_market + γ·r_sector + ε_idio + J_event + κ·(lnV − lnP)/D + I_player
```

| 项 | 定义 |
|---|---|
| `r_market` | 大盘因子：三状态隐马尔可夫（牛/震荡/熊），日级小概率转移（转移矩阵在 config），决定当日漂移与波动放大系数；日内为带漂移的高斯步 |
| `r_sector` | 板块因子：低幅度 AR(1) 共同冲击，γ 默认 0.5–0.8 |
| `ε_idio` | 个股特质噪声：学生 t 分布（ν=4，肥尾），σ 按附录 A 波动档校准 |
| `J_event` | 事件冲击：新闻/财报的即时跳变 + 数日衰减漂移（§4.3） |
| 锚定项 | `V` 为隐藏内在价值（EPS × 行业市盈率过程），κ 小、D 为回复期（日级）；保证长期不脱离基本面 |
| `I_player` | 玩家冲击：玩家净买卖流引起的临时冲击（随 tick 衰减）+ 小比例永久冲击，λ·(净流量/日均量) |

价格四舍五入到 0.01 元；触及涨跌停即钉板（§4.5）。

### 4.3 事件与信息面

- **新闻**：泊松到达（全市场/板块/个股三级，日均次数在 config）。类型库共 30 种
  （附录 B），各带冲击分布（对数收益区间）与衰减天数。新闻先推送标题，冲击在随后
  3–10 个 tick 内逐步释放——读新闻抢单是有效策略。
- **财报**：每股每 60 交易日一期，披露日按股票错开。披露前 5 个交易日进入"财报
  日历"（全站可见）。财报 = 隐藏基本面 EPS 的带噪观测；`surprise = 披露值 − 市场
  预期（上期外推）`，披露时按 surprise 比例跳变并带 1–3 日漂移。
- **确定性**：所有随机数出自持久化种子的 PRNG（xoshiro128**；主种子 + 日编号派生
  当日子流）。重启补跑结果一致。

### 4.4 盘口与撮合

- 玩家为价格接受者，NPC 合成流动性。**五档盘口**由引擎按流动性参数围绕现价合成，
  玩家未成交限价单真实并入对应档位显示。
- **市价单**：按现价 + 冲击滑点成交；滑点 = k·√(委托量/该股日均量)，向不利方向取整
  到分。小单无感，大单有感。
- **限价单**：入队，现价穿越委托价即成交（价格优先、时间优先的简化实现：同价位
  按提交 tick 排序）。
- **集合竞价**（开盘 3 分钟/收盘 1 分钟）：仅接受限价单，可挂撤；以"模型参考价 +
  玩家净需求失衡调整"产生单一成交价，可成交委托按该价撮合；未成交限价单转入
  连续竞价（收盘竞价后未成交则日终撤销）。
- **成交回报**：经 WebSocket 即时推送（含逐笔费用明细）。

### 4.5 涨跌停钉板

- 涨跌停价 = 昨收 ×(1±幅度)，四舍五入到分。
- 封板期间：对手方向委托即时成交；同方向委托排队，每 tick 以时间优先 + 概率放量
  部分成交（模拟"涨停买不进、跌停卖不出"）；板上概率与封单强度参数在 config。

## 5. 交易规则（照搬 A 股）

| 规则 | 取值 |
|---|---|
| 交易单位 | 买入 100 股整数倍；卖出可零股（送转碎股可一次卖出） |
| T+1 | 当日买入次日可卖（日终解冻）；卖出资金当日可用 |
| 涨跌停 | 主板 ±10%，创业板 ±20%，ST ±5%，IPO 首日 +44%/−36% |
| 佣金 | 成交额万 2.5，最低 5 元，双向 |
| 印花税 | 成交额 0.05%，仅卖出 |
| 过户费 | 成交额万 0.1，双向 |
| 委托 | 限价单/市价单；当日有效；可撤单；集合竞价时段仅限价单 |
| 幂等 | 下单携带 clientKey，重复提交去重 |
| 取整 | 各项费用逐笔四舍五入到分；价格最小变动 0.01 元 |

**资金冻结**：限价买冻结 `价×量+费用上限`，成交按实际费用清算并释放多余冻结；
市价买按现价上浮 2% 缓冲冻结，未成交部分即时释放。卖出冻结持仓股数。

**资产口径（全站唯一）**：总资产 = 可用资金 + 冻结资金 + 持仓市值 − 未偿贷款本息。
排行榜、杠杆约束、强平、破产判定均用此口径。

## 6. 公司生命周期

- **分红**：财报盈利公司按派息倾向（附录 A：高/中/低/无 → 派息率 60%/30%/10%/0，
  基数为该期 EPS）于财报日 +3 交易日除息：昨收基准价下调、现金红利扣 **10% 红利税**
  入账并记流水。
- **ST**：连续 2 期财报亏损 → 戴帽（±5%，全站公告）；摘帽条件：连续 2 期盈利。
- **退市**：ST 后再亏 1 期或净资产为负 → 进入 20 交易日退市整理期（全程标示），
  到期摘牌，持仓按最后价 **30% 现金回收**（记流水）。
- **IPO**：有股摘牌即触发（另有低概率随机 IPO），同行业新股上市补池，池子恒约
  48 只。首日 ±44%/−36%，次日起按板块正常幅度。V1 无打新，首日直接可买。

## 7. 账号与安全

- 注册：用户名（2–16 字符，唯一，允许中英文数字下划线）+ 密码（≥8 位）。
  argon2id 哈希。每 IP 每日最多注册 5 个；登录失败 5 次/15 分钟锁定。
- 会话：服务端会话表 + HttpOnly/SameSite=Lax/Secure Cookie，30 天滑动过期，可踢下线。
- 初始资金 ¥100,000，注册即记 ledger 第一条（type=GENESIS）。
- 无邮箱体系；忘记密码 → 管理员后台重置（§15）。
- 防护：zod 全接口入参校验、@fastify/rate-limit 速率限制、参数化 SQL、
  自定义请求头 + SameSite 防 CSRF、服务端全权威。

## 8. 信誉系统（350–850，初始 600）

| 事件 | 变动 |
|---|---|
| 按期还清一笔贷款 | +15 |
| 提前还清一笔贷款 | +20 |
| 逾期中 | 每交易日 −8 |
| 被强制平仓 | 一次 −80 |
| 破产 | 直接置为 400 |
| 完成打工班次 | +1（每 20 交易日经此途径最多 +10） |

信誉的作用：贷款额度与利率档位（§9）、逾期/强平状态全站禁止新贷款与高薪岗
准入、"基金经理"职位要求信誉 ≥700（§10）。信誉变动全部记 `credit_events` 流水。

## 9. 贷款系统（NPC"布偶银行"）

**产品**：信用贷。期限档 20/60/120 交易日；单利，每交易日结算计提利息；到期一次
还本；支持随时部分/全额提前还款（还款先冲抵已计提利息，再冲本金）。

**额度与利率查表（按申请时信誉分）**

> `额度 = 信誉分 × cfg.loans.capPerCreditPoint`（默认 `500_000` 分 = ¥5,000/分，
> 即「个人信誉分 × 5000 元」）。信誉 600 → **¥3,000,000**。

> 另注：额度与总杠杆约束**都正比于信誉分**，故谁先拒只取决于净资产

**总杠杆约束**（与查表额度取严）：未偿本息合计 ≤ 净资产 ×（信誉分 ÷ 300）。

**逾期链条**：到期未还 → 宽限 3 交易日（罚息 2 倍利率）→ 逾期状态（每日 −8 信誉，
禁新贷款/高薪岗）→ 逾期第 10 交易日触发**强制平仓**：系统以市价单按持仓市值从大到
小逐笔卖出（滑点、费用照算，流水可查）直至清偿。

**破产**：强平后仍资不抵债 → 破产结算：剩余资产清零、债务豁免、信誉置 400、发放
救济金 **¥20,000**（非 10 万，防"梭哈失败重开"成为优势策略）、`bankrupt_count+1`
并在排行榜永久标注。

## 10. 打工与能力

**能力 6 项**（各 0–10 级）：学历、编程、金融、体能、沟通、设计。

**课程升级**：Lv n→n+1 费用 `5000×1.6ⁿ` 元、时长 `(n+1)×8` 游戏小时（= (n+1)×20
现实分钟）。报名扣费并占用时间线；期间不可打工/报其他课，可交易；到点自动结业
（离线照常）。单项练满累计约 ¥90.8 万——高能力是长线投资。

**班次**：一班 = 8 游戏小时 = 20 现实分钟；可预约排队；**每游戏日最多开始 2 班**
（按班次开始时刻所属交易日计）；班次开始后不可取消，结束自动发薪并记流水。
上班期间不可上课/另开班，可交易。

**工资公式**：`实发 = 基础工资 × (1 + 0.05 × Σ超出该职业各要求项的能力点数)`。

|---|---|---|
| 传单派发员 | 无 | ¥800 |
| 外卖骑手 | 体能2 | ¥1,500 |
| 在线客服 | 沟通2 | ¥1,600 |
| 家教 | 学历3 | ¥2,500 |
| 平面设计师 | 设计3+沟通1 | ¥2,800 |
| 会计 | 金融4+学历2 | ¥3,800 |
| 初级程序员 | 编程4+学历3 | ¥4,000 |
| 高级工程师 | 编程7+学历5 | ¥8,000 |

| 基金经理 | 金融9+学历7+信誉≥700 | ¥15,000 |

**平衡意图**：打工是保底现金流与东山再起通道，期望收益显著低于会玩的炒股；顶级
岗位前置投入（课程费数十万 + 数百现实小时）使其定位为后期对冲，而非最优策略。
全部系数在 config，后台可调。

## 11. 前端信息架构（手机优先，桌面自适应）

底部 5 Tab：
1. **首页**：总资产曲线、今日盈亏、持仓/可用/负债/信誉四卡片、进行中的班次与课程。
2. **行情**：综合指数分时、板块热力图、涨跌幅榜、搜索；顶部入口进全市场新闻流。
   → **个股页**：分时/日 K 切换（lightweight-charts）、五档盘口、买卖面板（含费用

4. **榜单**：总资产榜、收益率榜；破产标注。

隐藏路由 `/admin`（§15）。桌面端同一 SPA 响应式放大（行情+盘口+K 线三栏）。

## 12. API 与 WebSocket 概要

REST（均为 `/api` 前缀，会话 Cookie 鉴权）：
- auth：`POST /auth/register`、`POST /auth/login`、`POST /auth/logout`、`GET /me`
- 行情：`GET /market/overview`、`GET /stocks`、`GET /stocks/:code`、
  `GET /stocks/:code/candles?type=day|tick`、`GET /news`
- 交易：`POST /orders`（clientKey 幂等）、`DELETE /orders/:id`、`GET /orders`、
  `GET /trades`、`GET /ledger`
- 银行：`GET /bank/products`、`POST /bank/loans`、`POST /bank/loans/:id/repay`、
  `GET /bank/loans`、`GET /credit`
- 生活：`GET /jobs`、`POST /shifts`、`DELETE /shifts/:id`（未开始）、`GET /shifts`、
  `GET /abilities`、`POST /courses/enroll`
- 其他：`GET /leaderboard`、`GET /healthz`（无鉴权）
- 管理：`/admin/*`（用户列表/重置密码/封禁/公告/config 调整/备份下载/引擎状态）

WebSocket `/ws`（Cookie 鉴权）：
- ↓ `{t:'tick', day, phase, quotes:[[code,price,chgPct,vol],…]}`（订阅集合）
- ↓ `{t:'fill'|'orderUpdate', …}`（私有成交/委托回报）
- ↓ `{t:'news', item}`、`{t:'notice', …}`（公告/结算摘要）
- ↑ `{t:'sub', codes:[…]}`

错误响应统一 `{code, message}`；业务错误码表在实现计划中固化（资金不足/超出涨跌
停/非交易时段/T+1 限制/超杠杆/信誉不足等）。

## 13. 数据模型（SQLite，19 表）

`users`（含 cash_available/cash_frozen/credit/bankrupt_count/status）、`sessions`、
`stocks`（seed 参数）、`stock_state`（现价/昨收/涨跌停价/ST 状态/内在价值等）、
`candles_day`、`ticks`（滚动保留最近 3 交易日）、`orders`、`trades`（逐笔费用）、
`holdings`（qty_total/qty_sellable/avg_cost）、`ledger`（只追加，含 balance_after）、
`loans`、`credit_events`、`jobs`、`shifts`、`abilities`、`enrollments`、
`news`、`reports`、`dividends` 共 19 张业务表；另有 4 张系统表：`config`、
`engine_state`（单行快照）、`announcements`、`admin_logs`。合计 23 张，最终以
迁移脚本为准。

约束要点：ledger append-only（无 UPDATE/DELETE）；orders/trades 外键完整；
holdings 非负；所有金额以"分"为整数存储，展示层转元。

## 16. 测试策略（实现阶段 TDD）

1. **规则单测**：费用计算与四舍五入、涨跌停价、T+1 解冻、集合竞价定价、滑点、
   利息计提/罚息、信誉转移、强平顺序、破产清算、工资/课程公式、分红除权。
2. **不变量（property-based，随机操作序列 + 快进 ≥1000 游戏日）**：
   - 每用户：`Σledger = cash_available + cash_frozen`；
   - 全局复式记账：引入系统虚拟账户（市场对手方、布偶银行、税务、雇主、清算），
     每笔业务的 ledger 分录两侧配平，全体账户（用户+系统）净变动恒为 0；
   - holdings 恒非负、冻结与在途委托一致、无孤儿委托。
3. **确定性**：同种子重放同轨迹；**补跑一致性**：运行 N 日 vs 中途杀进程重启补跑，
   最终状态逐字段一致。
4. **API 集成**：注册→登录→下单→成交→流水→贷款→打工全链路；权限与限流。
5. **冒烟负载**：50 并发 WS 客户端 + 每秒下单，tick 延迟 < 1s。

## 20. 风险与权衡（已知取舍）

| 风险 | 处置 |
|---|---|
| SQLite 单写者 | 单进程同步事务即串行化；体量远低于上限；WAL 提升读并发 |
| 单容器单点 | 接受（体量小）；补跑机制使短停机无损；每日备份兜底 |
| 平台锁定 Zeabur | Docker 镜像可整体迁移，仅重配环境变量与卷 |
| `zeabur.app` 大陆访问速度中等 | 接受；后续可绑自有域名（二期，需求方购买） |
| 玩家自成交拉抬（对倒） | 冲击大部分为临时项 + 双向费用 + 价值锚回复，对倒亏费用；玩家间无转账，收益无法转移 |
| 挂机收益失衡 | 每日班次上限 + 信誉加分上限 + config 可调 |
| 时钟漂移 | 以墙钟为权威，tick 按绝对时刻调度，漂移自动追平 |
